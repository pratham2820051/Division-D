2. CURRENT ARCHITECTURE (AS-IS AFTER INTEGRATION PASS)
================================================================================

BACKEND (FastAPI, feature-first)
--------------------------------
  main.py mounts:
    /api/v1/chat/*         Chat CRUD + send_message
    /api/v1/memory/*       history + context (parallel to chat GET)
    /api/v1/voice/*        transcribe, speak, synthesize (alias)
    /api/v1/translation/*  translate

  Chat send path:
    chat_routes.send_message
      → chat_service.send_message
          → memory_service.add_message (user)
          → memory_service.get_recent_context
          → chat_orchestrator.process(user, context, language)
          → localization.localize_blocks (if language != en)
          → memory_service.add_message (assistant blocks × N)

  Voice / Translation / Memory are NOT invoked from HTTP handlers directly;
  chat_service now calls translation_service internally via localization.py.

FRONTEND (Next.js)
------------------
  Chat UI:
    ChatInterface → useChatOrchestration → chatService (real API)
    conversationStore (Zustand + localStorage)

  Voice UI:
    ChatInput → VoiceMode → useVoiceInput → voiceService.transcribeAudio (real)
    ChatInput → onVoiceSend → sendVoiceMessage → chat with [voice] prefix

  Translation UI:
    MessageTranslateMenu → translationService (NOW real API)
    ChatHeader TranslationDropdown → store.language → chat send + backend localize

  Memory / history:
    selectConversation → getChatHistory (GET /api/v1/chat/{id}) when synced=true
    /api/v1/memory/* still unused on frontend (chat GET is sufficient today)

7. BLOCKERS
================================================================================

1. MOCK AI / TRIAGE
   ChatOrchestrator uses keyword rules. RAG, confidence_scoring HTTP routes,
   and DiagnosisOrchestrator are not connected to POST .../message.

2. MOCK VOICE / TRANSLATION PROVIDERS
   Real Faster Whisper and Edge TTS stubs raise NotImplementedError.
   Translation uses MockTranslationProvider despite real HTTP route.

3. NO DATABASE
   memory is InMemoryChatStore. Server restart loses chats. Frontend
   localStorage can diverge from backend unless synced flag is set.

4. ASYNC/SYNC BRIDGE
   localization.py uses asyncio.run() inside sync chat_service.send_message.
   Works for tests and sync routes; may need refactor if chat becomes async
   or under nested event loops.

5. LANGUAGE NOT IN PUBLIC RESPONSE SCHEMA
   SendMessageResponse does not expose language field (internal dict only).
   Public API contract unchanged per requirement.

6. STT LANGUAGE DETECTION UNUSED
   TranscribeResponse.language is returned but not forwarded to chat send
   or store (could set source_language for translation later).
